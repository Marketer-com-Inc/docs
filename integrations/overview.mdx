Integrations bring source data into your Marketer workspace. Connect only the accounts and resources that belong to the workspace you are configuring.

<Note>
  Owners, Admins, and Members can manage connections. Viewers can inspect available connection state but cannot connect, reconnect, change selections, sync, or disconnect.
</Note>

## Before you connect

- Confirm that you are in the correct Marketer workspace.
- Use a provider identity that can access the accounts, stores, properties, or Slack workspace you need.
- Decide which individual resources should contribute data. You do not have to select everything the provider exposes.
- Ask an Owner or Admin about workspace policy before granting access to a production account.

Marketer shows the permissions and resources available through each provider flow. The provider remains the source of truth for the access your identity can grant.

## Connect a source

<Steps>
  <Step title="Open Integrations">
    In Marketer, select **Integrations** in the main navigation.
  </Step>
  <Step title="Choose a provider">
    Open its row to see the current connection state, available actions, and setup requirements.
  </Step>
  <Step title="Authorize and select resources">
    Complete the provider flow or enter the requested credential. Then choose the accounts, stores, properties, or channel settings that belong in this workspace.
  </Step>
  <Step title="Confirm the first successful state">
    Look for **Connected**, the selected resources, a completed sync or configured Slack channel, and any available data-coverage details.
  </Step>
</Steps>

## Understand freshness

A connected badge confirms authorization. It does not guarantee that every source has finished importing or that every metric has the same reporting delay.

Use the provider detail page to check sync progress, last sync, selected resources, and data coverage. Compare important decisions with the source platform when the latest period is still changing.

## Recover or remove a connection

- Use **Resync** when authorization is healthy but imported data needs to be refreshed.
- Use **Reconnect** when a provider revoked access, required new permissions, or no longer exposes a selected resource.
- Refresh the page when Marketer says the status could not be verified. Marketer preserves the last-known connection instead of treating a read error as a disconnect.
- Use **Disconnect** only when the workspace should stop using that source. Review the confirmation because downstream reporting and workflows can lose context.

For a diagnostic sequence, see [Troubleshoot integrations](/integrations/troubleshooting).

## Next step

After the first sync completes, ask Marketer a narrow, read-only question about the connected source. Include the account and date range so you can verify the answer against the provider.
