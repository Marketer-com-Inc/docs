**Awaiting action** is the workspace inbox for work that cannot continue without a human decision. It brings together recorded approvals, paused workflow decisions, and links back to proposals that need review.

An item here describes a pending decision. It is not evidence that the proposed change already happened.

## Know which decision you are making

Marketer exposes two distinct review points.

| Review point | Where it appears | What the decision does |
| --- | --- | --- |
| Proposed agent or pipeline run | Inside the conversation | Decides whether the listed plan may start. |
| Proposed connected-account or workflow action | **Awaiting action** in Quick actions | Records whether the specific change or paused run may continue. |

The controls and consequences are different. Review the complete item before selecting a button.

## Review a proposed run in chat

Longer agent work can begin with a step-by-step proposal.

### Read the proposal

1. Match the proposal title to the outcome you requested.
2. Expand **Steps** and read the full sequence.
3. Confirm the plan gathers the intended workspace context and evidence.
4. Check the production or action steps against your authority boundary.
5. Confirm the final step returns the artifact or result you need.

Then use the displayed controls. A named specialist can show **Cancel**, **Edit**, and **Accept & Run**; Creative Pipeline can show **Cancel**, **Edit**, and **Approve & Run**; another task plan can show **Cancel**, **Edit brief**, and **Run it**.

After the displayed run control is selected, follow the task until it is completed, waiting, partial, failed, or canceled. This decision approves the listed run—not every action its result might later recommend.

## Open the Awaiting action inbox

Open **Awaiting action** from Quick actions. The page title is **Awaiting your action** and the description identifies it as pending approvals and proposals that need a human decision.

The page can show decidable approval rows above a feed of other pending items. Start with rows that have **Approve** and **Reject** controls, then use linked feed items to open their full source context.

## Decide an agent-proposed change

A connected-account proposal row can show:

- The affected entity or object name
- The action or tool that proposed the change
- Who or what submitted it, plus its age
- A spend-impact badge when that impact is known
- The reason for the proposal
- One or more fields shown as current value → proposed value
- The relevant ad-account identifier when available

<Steps>
  <Step title="Confirm the object">
    Match the entity name, provider account, and object level to the record you intended to change. Similar names are not enough.
  </Step>
  <Step title="Read the diff">
    Review every current value and proposed value. If the item says it did not record a change summary, open the source tool or conversation and do not approve from the incomplete row.
  </Step>
  <Step title="Check impact and evidence">
    Confirm the size and direction of the change, the reason, the supporting measurement window, and the workspace guardrail that permits it.
  </Step>
  <Step title="Choose Approve or Reject">
    Select **Approve** only when the recorded object and diff are correct. Select **Reject** when the scope is wrong, stale, unsafe, or unsupported.
  </Step>
  <Step title="Read the confirmation">
    Approval opens **Approve this change?** Read the account and spend warning, then select **Approve** again to record the decision or **Cancel** to return without deciding.
  </Step>
</Steps>

An approval gives the proposing agent permission to apply that specific change. The change is not complete until Marketer runs it; verify the result in the owning product surface and, when needed, the connected account.

## Decide a paused workflow run

A workflow approval row identifies a specific scheduled or triggered run that paused. It can show:

- The requested decision and workflow name
- A **Paused** badge
- The action and number of items that will change
- A list of affected entities, followed by an additional count when the list is longer
- When that entity set was picked
- Whether other runs of the same workflow are also waiting
- **Approve**, **Reject**, and **Review the automation** controls

### Review the scope

Select **Review the automation** when you need to inspect the trigger, steps, or guardrails that created the decision. Return to the pending row and compare the configuration with the scope shown there.

If the row says the workflow did not record what it will change, review the automation before approving. Missing scope is not evidence of a zero-impact change.

### Choose the branch

- **Approve** opens **Let this automation continue?** The dialog restates what the current run will do. Confirming releases that run to continue immediately.
- **Reject** stops the current paused run from continuing.
- **Review the automation** leaves the decision pending while you inspect its configuration.

When several runs of the same workflow are waiting, the decision applies only to the run shown. The remaining runs stay paused. After you decide, the interface can show a **Decision sent** receipt while other runs remain unresolved; their own approval rows appear as the workflow progresses.

<Warning>
  A recurring workflow can have more than one paused run, each with its own selected entities. Do not assume one approval resolves every pending run for that workflow.
</Warning>

## Follow a linked pending item

Some items in the lower feed open the conversation, creative review, workflow, or task that owns the decision rather than exposing buttons directly in the inbox.

1. Open the linked row.
2. Read the full request, result, and current status.
3. Make the decision in the owning surface.
4. Return to **Awaiting action** and confirm the item is no longer unresolved.

Use the notification's summary for wayfinding only. The linked record supplies the scope you need for the decision.

## Verify what happened after the decision

Do not stop at the success message. Follow the chain for the item you decided:

| Decision | Immediate state to verify | Final state to verify |
| --- | --- | --- |
| Start the displayed task proposal | The card becomes queued or working | The task result and any output link |
| Approve an agent-proposed account change | The proposal records the approval and leaves the pending list | The updated object in **Campaigns** and, when needed, the provider |
| Reject an agent-proposed change | The proposal can no longer proceed | No unintended object change occurred |
| Approve a workflow run | The selected run resumes | The run history shows its output or resulting action |
| Reject a workflow run | The selected run stops | The run history records that it did not continue |
| Decide one of several workflow runs | A decision receipt can replace that row | Other paused runs remain available for separate decisions |

If an approved change is still processing, keep the original decision and task open. Do not submit a duplicate proposal.

## Use a material-change review

Before approving work that can affect spend, targeting, delivery, or customer-facing material, verify:

1. **Workspace and provider:** the intended workspace and connected account.
2. **Object:** the exact campaign, ad set, ad, workflow, or creative.
3. **Current and proposed state:** every visible field in the diff or run scope.
4. **Magnitude:** the budget, status, audience, count, or delivery impact.
5. **Evidence:** source, date window, attribution context, and freshness.
6. **Guardrail:** the applicable business constraint and approval authority.
7. **Result check:** where you will confirm the provider or product state afterward.

## If the decision cannot be completed

<AccordionGroup>
  <Accordion title="The row lacks a usable change summary">
    Open the proposing conversation or tool. Request the exact object, current value, proposed value, and effect. Reject or leave the item pending until it is independently understandable.
  </Accordion>
  <Accordion title="Approve or Reject is unavailable">
    Confirm the workspace, your role, the proposal state, and the connected account. Another authorized member may already have decided it.
  </Accordion>
  <Accordion title="The proposal is stale">
    Reject it or leave it unresolved, refresh the underlying analysis, and create a new proposal from current provider state.
  </Accordion>
  <Accordion title="Approval succeeded but the object has not changed">
    Approval and application are separate. Check the task or workflow state, then verify provider processing before considering a retry.
  </Accordion>
  <Accordion title="A workflow approval returns after a decision">
    Check whether it is a different run of the same automation. Compare the requested time and selected entities; each paused run requires its own decision.
  </Accordion>
</AccordionGroup>
